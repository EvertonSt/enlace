1. PROJECT OVERVIEW
================================================================================

Enlace is a full-stack ISP (Internet Service Provider) management platform
designed for small-to-medium fiber ISPs in Brazil. It provides:

  • A customer-facing mobile app (iOS/Android) for checking plans, bills,
    outages, and support tickets.
  • A customer-facing web portal with the same features.
  • A NOC (Network Operations Center) desktop app for internal staff to
    manage outages, dispatch technicians, and handle support queues.
  • A backend API server with AI-powered ticket triage (Claude, OpenAI,
    or rule-based fallback).

The entire platform is built as a TypeScript monorepo managed by pnpm
workspaces and Turborepo.

3d. SERVER (apps/server)
--------------------------------------------------------------------------------

Platform:   Fastify 5 + Prisma 7 + PostgreSQL
Package:    @enlace/server

API Routes (all under /api prefix):
  • POST /api/auth/register   — Register new customer account
  • POST /api/auth/login      — Login, returns JWT token
  • GET  /api/auth/me         — Get current user info (authenticated)
  • GET  /api/tickets         — List tickets (customers see own, staff see all)
  • GET  /api/tickets/:id     — Get ticket details
  • POST /api/tickets         — Create ticket + AI triage
  • PATCH /api/tickets/:id    — Update ticket status/priority
  • GET  /api/tickets/:id/triage — Get AI triage result for a ticket
  • GET  /api/outages         — List all outage events
  • GET  /api/outages/:id     — Get outage details
  • POST /api/outages         — Create outage (authenticated)
  • PATCH /api/outages/:id    — Update outage status
  • GET  /api/customers       — Customer endpoints (in routes/customers.ts)
  • GET  /api/invoices        — Invoice endpoints (in routes/invoices.ts)
  • GET  /api/plans           — Plan endpoints (in routes/plans.ts)
  • GET  /api/health          — Health check (no auth)

AI Triage System:
  • Supports 3 providers: Claude (Anthropic), OpenAI, rule-based
  • Configured via TRIAGE_PROVIDER env var
  • Automatic fallback: if primary provider fails, falls back to rule-based
  • 15-second timeout per triage call
  • Returns: urgency score (1-5), category, suggested response, provider info

Authentication:
  • JWT tokens (7-day expiry)
  • bcrypt password hashing (12 rounds)
  • Fastify preHandler middleware for protected routes
  • Role-based access: customer (own data only), staff (all data), admin

Database Models (Prisma schema):
  • User — email, password (hashed), name, role (customer/staff/admin)
  • Plan — name, speed (Mbps), data cap (GB), price (BRL)
  • Customer — linked to User + Plan, has phone, address, status
  • Ticket — subject, body, status, priority, category, aiTriage (JSON)
  • OutageEvent — title, description, status, affected area/count, times
  • Invoice — amount, due date, status, lineItems (JSON)
  • TechnicianJob — linked to Ticket, status, schedule, notes, location

3e. CORE PACKAGE (packages/core)
--------------------------------------------------------------------------------

Package: @enlace/core — shared across ALL apps

Exports:
  • Zod schemas & TypeScript types for every domain entity:
      Customer, Plan, Ticket, OutageEvent, Invoice, TechnicianJob
  • Status/priority/category enums
  • AI triage result schema
  • CreateTicketRequest schema (used for validation on both client & server)
  • Typed API client (apiFetch, api.get/post/put/patch/delete)
  • configureApiClient() to set base URL and token provider
  • i18n resources (en.json, pt-BR.json)

This package is the single source of truth. When the server returns a Ticket,
the TypeScript type is shared with the mobile, web, and desktop apps — no
code duplication, no type mismatches.

5. ENVIRONMENT VARIABLES REFERENCE
================================================================================

SERVER (apps/server/.env):
  DATABASE_URL          PostgreSQL connection string
                       Example: postgresql://user:pass@localhost:5432/enlace
  PORT                 Server port (default: 3001)
  HOST                 Bind address (default: 0.0.0.0)
  JWT_SECRET           Secret key for JWT signing (change in production!)
  TRIAGE_PROVIDER      "claude" | "openai" | "openai-compatible" | "rule-based"
  ANTHROPIC_API_KEY    Required if TRIAGE_PROVIDER=claude
  OPENAI_API_KEY       Required if TRIAGE_PROVIDER=openai
  OPENAI_BASE_URL      Optional override for OpenAI-compatible providers
  OPENAI_MODEL         Optional model override (default: gpt-4o)
  CLAUDE_MODEL         Optional model override (default: claude-sonnet-4-20250514)

WEB/DESKTOP (for future API integration):
  VITE_API_URL         Backend API URL (default: http://localhost:3001)

MOBILE:
  EXPO_PUBLIC_API_URL  Backend API URL (for future use)

   cd apps/server

   pnpm db:push        # Creates all tables in the database

7d. Connecting Frontend to Backend
--------------------------------------------------------------------------------

The frontends currently use hardcoded mock data. To connect them:

1. In the mobile app (src/i18n.ts or a new src/lib/api.ts):
   import { configureApiClient } from '@enlace/core';
   configureApiClient({
     baseUrl: process.env.EXPO_PUBLIC_API_URL ?? 'http://localhost:3001',
     getToken: () => SecureStore.getItemAsync('auth-token'),
   });

2. In the web app (src/lib/api.ts):
   import { configureApiClient } from '@enlace/core';
   configureApiClient({
     baseUrl: import.meta.env.VITE_API_URL ?? 'http://localhost:3001',
     getToken: () => localStorage.getItem('auth-token'),
   });

3. Replace mock data in each screen with API calls:
   // Before (mock):
   const TICKETS = [{ id: '1', subject: '...' }];

   // After (real):
   import { api } from '@enlace/core';
   const [tickets, setTickets] = useState([]);
   useEffect(() => {
     api.get('/api/tickets').then(setTickets);
   }, []);

4. Implement auth flow:
   - Login screen calls POST /api/auth/login
   - Store JWT token in SecureStore (mobile) or localStorage (web)
   - configureApiClient's getToken returns the stored token
   - After login, redirect to dashboard

--------------------------------------------------------------------------------

  npm install -g netlify-cli
  cd enlace

  3. Connect your GitHub repository
  4. Configure build settings:

  5. Add environment variables:

     • Base directory: apps/web
     • Build command: pnpm install --frozen-lockfile && pnpm build
     • Publish directory: dist

  Netlify may need a netlify.toml in apps/web/:
     [build]
     command = "pnpm install && pnpm build"
     publish = "dist"

     [[redirects]]
     from = "/*"
     to = "/index.html"
     status = 200

  2. Import your GitHub repository
  3. Framework preset: Vite
  4. Root directory: apps/web
  5. Build command: pnpm install && pnpm build
  6. Output directory: dist
  7. Add environment variable: VITE_API_URL
  8. Deploy

  For monorepo detection, Vercel usually auto-detects. If not:
  Create vercel.json at the root:

     • Start command: cd apps/server && pnpm start
     • Port: 3001
  4. Create a PostgreSQL database (Render → New → PostgreSQL)

  6. Add other env vars (JWT_SECRET, TRIAGE_PROVIDER)
  7. Deploy

  2. cd apps/server
  3. fly launch (creates fly.toml)
  4. fly volumes create enlace_data --region gru  (São Paulo)
  5. Set secrets: fly secrets set DATABASE_URL=... JWT_SECRET=...
  6. fly deploy

  Create a Dockerfile in apps/server/:
     FROM node:22-slim
     WORKDIR /app
     COPY package.json pnpm-lock.yaml ./
     RUN corepack enable && pnpm install --prod
     COPY prisma ./prisma/
     COPY src ./src/
     RUN npx prisma generate
     EXPOSE 3001
     CMD ["node", "dist/index.js"]

After deployment, remember to:
  - Run the seed script against the production database:
    DATABASE_URL=<prod-url> pnpm db:seed
  - Set TRIAGE_PROVIDER to "claude" or "openai" if you want AI triage
  - Set a strong JWT_SECRET (not the dev default)

All endpoints return JSON. Protected endpoints require:
  Authorization: Bearer <jwt-token>

AUTH:
  POST /api/auth/register     Body: { email, password, name, phone?, address? }
                              Returns: { token, user, customer }

  POST /api/auth/login        Body: { email, password }
                              Returns: { token, user, customer }

  GET  /api/auth/me           Returns: { id, email, name, role, customer }

TICKETS:
  GET  /api/tickets           Returns: Ticket[] (filtered by role)
  GET  /api/tickets/:id       Returns: Ticket (with customer)
  POST /api/tickets           Body: { customerId, subject, body }
                              Returns: Ticket (with AI triage result)
  PATCH /api/tickets/:id      Body: { status?, priority?, category? }
                              Returns: Ticket
  GET  /api/tickets/:id/triage Returns: { ticketId, triage }

OUTAGES:
  GET  /api/outages           Returns: OutageEvent[]
  GET  /api/outages/:id       Returns: OutageEvent
  POST /api/outages           Body: { title, affectedArea, description? }
                              Returns: OutageEvent (auth required)
  PATCH /api/outages/:id      Body: { status?, estimatedResolution? }
                              Returns: OutageEvent (auth required)

CUSTOMERS:
  GET  /api/customers         Returns: Customer[] (role-filtered)
  GET  /api/customers/:id     Returns: Customer
  PATCH /api/customers/:id    Body: { planId?, status?, ... }

INVOICES:
  GET  /api/invoices          Returns: Invoice[]
  GET  /api/invoices/:id      Returns: Invoice
  POST /api/invoices          Body: { customerId, amount, dueDate, ... }
  PATCH /api/invoices/:id     Body: { status? }

PLANS:
  GET  /api/plans             Returns: Plan[]
  GET  /api/plans/:id         Returns: Plan

HEALTH:
  GET  /api/health            Returns: { status, timestamp, triageProvider }
